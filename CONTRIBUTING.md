# Contributing guide

AQUA-claima follows the contribution workflow of
[AQUA-diagnostics](https://github.com/DestinE-Climate-DT/AQUA-diagnostics/blob/main/CONTRIBUTING.md):
issues with the templates in `.github/ISSUE_TEMPLATE` (a **Design proposal** for big changes), pull requests from
`main` with the Standard PR template, one CHANGELOG line per PR, and merges done by the maintainers only.

## Testing and CI

Tests are run with `pytest -m claima`. All suites call `aqua-claima-test-reusable.yml`, which reuses the composite
actions of aqua-core (`setup-test-data`, `setup-aqua`, `pytest-reports`).

| Workflow | When it runs | Install mode |
|---|---|---|
| `aqua-claima.yml` | PR with the `run tests`, `ready for review` or `ready to merge` label, push to `main`, manual | `cross-check` until aqua-core 1.3.0 and aqua-diagnostics 0.27.0 are released, then `local` |
| `aqua-claima-pypi.yml` | manual (scheduled once aqua-claima is on PyPI) | `pypi` |
| `aqua-claima-ruff.yml` | every push | - |
| `conda-relock.yml` | every Tuesday, PR with the `conda-lock` label, manual | - |

Install modes:

- `local`: `conda-linux-64.lock` (generated by `conda-relock.yml`, never by hand) plus the checkout.
- `cross-check`: `environment.yml`, then aqua-core and aqua-diagnostics from git refs (workflow inputs).
- `pypi`: `environment-pypi.yml` plus `aqua-claima[tests]` from PyPI, tested against its release tag.

The workflows need these repository secrets: `AQUA_GITHUB_PAT`, `AQUA_DVC_PAT`, `AQUA_DVC_PEM`,
`AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `POLYTOPE_KEY`, `CODECOV_TOKEN` (optional).

## Coding style

Ruff selectors are `E,F,I,W,N`: run `pre-commit run --all-files` with the `ruff` pinned in the `style` extra.
